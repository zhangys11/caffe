### 2.2 预测脚本的输入与输出（Inputs & Outputs of the Prediction Script）

本节说明预测脚本的输入与输出。脚本全文见《参考手册篇》脚本模板一章中的 pycaffe 图像分类预测脚本，这里只抽取与输入输出有关的关键片段。

**输入部分。** 脚本开头的注释块列出了预处理参数的含义：

```python
#定义使用的神经网络模型
#image_dims : dimensions to scale input for cropping/sampling.
#        Default is to scale to net input size for whole-image crop.
#    mean, input_scale, raw_scale, channel_swap: params for
#        preprocessing options.
```

中文说明：这段注释是英文原文，逐条对应下面的参数——`image_dims` 是输入缩放到裁剪/采样用的尺寸，默认按网络输入尺寸做整图裁剪；`mean`、`input_scale`、`raw_scale`、`channel_swap` 属于预处理选项。

分类器的构造片段如下：

```python
net = caffe.Classifier(MODEL_FILE, PRETRAINED, 
               mean=numpy.load(caffe_root +'python/caffe/imagenet/ilsvrc_2012_mean.npy').mean(1).mean(1),
               channel_swap=(2,1,0),
               raw_scale=255,
               # image_dims=(224, 224)
)
```

中文说明：输入由四部分组成——网络结构文件 `MODEL_FILE`（`deploy.prototxt`）、权重文件 `PRETRAINED`（`bvlc_googlenet.caffemodel`）、均值文件与预处理参数。均值文件用的是 Caffe 自带的 `python/caffe/imagenet/ilsvrc_2012_mean.npy`，脚本先对它做 `.mean(1).mean(1)` 再传入；`channel_swap=(2,1,0)` 与 `raw_scale=255` 是原文列出的预处理参数；`image_dims` 这一行在原文里被注释掉，没有生效。待分类的图片来自 `os.walk(caffe_root + "examples/images/")` 的遍历结果，逐张用 `caffe.io.load_image(IMAGE_FILE)` 读入。

**输出部分。** 类别序号与 top-5 标签的取法如下面的片段：

```python
       prediction = net.predict([input_image])
       print 'predicted class:',prediction[0].argmax()
```

中文说明：`net.predict([input_image])` 返回该图片的得分数组，`prediction[0].argmax()` 取其中最大的下标，即预测类别序号，被打印成 `predicted class: ...`。每张图片在预测前还会先打印一行形如 `---- <图片路径> ----` 的分隔行，便于在批量输出里区分图片。

```python
       top_k = net.blobs['prob'].data[0].flatten().argsort()[-1:-6:-1]
       print labels[top_k]
```

中文说明：`net.blobs['prob']` 是该网络的概率输出 blob，`.data[0]` 取第一张图片的概率，`.flatten()` 拉平成一维，`.argsort()` 返回升序排列的下标，`[-1:-6:-1]` 反向切出末尾 5 个，也就是概率最高的 5 个类别的下标；`labels[top_k]` 再用这些下标取出对应标签文本并打印。这里的 `labels` 就是脚本中读入的标签数组：

```python
imagenet_labels_filename = caffe_root +'data/ilsvrc12/synset_words.txt'
labels =numpy.loadtxt(imagenet_labels_filename, str, delimiter='\t')
```

中文说明：标签文件是 `data/ilsvrc12/synset_words.txt`，用 `numpy.loadtxt(..., str, delimiter='\t')` 按制表符 `\t` 逐行解析，因此 `labels[top_k]` 取到的是按制表符切分后的标签行。标签文件用什么格式，完全由这一行的读取方式决定。

> 提示：标签文件的格式在工程里存在两套互不相同的假设——DIGITS 的数据集准备脚本生成的 `labels.txt` 是每行一个数字（见第 3 章 3.3 节），而这里的预测脚本用 `numpy.loadtxt(..., delimiter='\t')` 按制表符解析。两者不一致时不会报错，而是静默解析失败（标签错位或取不到文本），换成自己的数据集时要以上面这条 `numpy.loadtxt` 的读取方式为准。

**CPU / GPU 模式的写法。** 原文这一段代码如下：

```python
#cpu模式

caffe.set_mode_gpu()
```

> 提示：原文这里的注释写的是「cpu模式」，但下一行调用的是 `caffe.set_mode_gpu()`，注释与实际调用不一致；原文代码按原样保留，实际使用时按自己的需求选择 CPU 或 GPU。

## 4 模型微调（Fine-tuning）

本章依次给出三个微调实例：官方 finetune_flickr_style 示例（4.1）、ROP 二分类微调（4.2）、GoogLeNet 多分类头改造（4.3）；4.4 在原稿中只有标题。完整的 solver 与 train_val 模板见《参考手册篇》配置模板一章中的微调 solver 模板与分类层片段。

### 4.1 微调基础：finetune_flickr_style 示例（Fine-tuning Basics）

原稿以 Caffe 自带的 `finetune_flickr_style` 为例（对应路径 `models/finetune_flickr_style/`）。它的 solver 用两条注释点出了微调与从头训练的区别：

| 参数取值 | 原文注释（英文） | 说明 |
| --- | --- | --- |
| `base_lr: 0.001` | `# lr for fine-tuning should be lower than when starting from scratch. Original AlexNet uses 0.01` | 微调的学习率应低于从头训练：原始 AlexNet 用 0.01，微调用 0.001 |
| `stepsize: 20000` | `# stepsize should also be lower, as we're closer to being done. Original AlexNet uses 100000` | stepsize 同样应更小：原始 AlexNet 用 100000，微调用 20000 |

这两条注释只在这里解释一次，4.2 的 ROP solver 沿用同样的取值与注释，不再重复。

网络侧只改动了分类层，原稿把这一节标注为「只列改动过的分类层」。改动要点有三条，都可以在同一段层定义里看到：

- 改层名：分类层从 AlexNet 的 `fc8` 改名为 `fc8_flickr`，对应注释 `# rename layer name`；
- 改 `num_output`：对应注释 `# change to your number of classes. Original AlexNet has 1000 classes`，示例把 `num_output` 设为 `20`；
- 把新层的 `lr_mult` 设得比其他层高：对应注释 `# lr_mult is set to higher than for other layers, because this layer is starting from random while the others are already trained`（这一层的权重是随机初始化的，其他层已经训练过）；示例中两个 `param` 分别取 `lr_mult: 10` / `decay_mult: 1` 与 `lr_mult: 20` / `decay_mult: 0`，并分别标注 `# Original AlexNet uses 1` 与 `# Original AlexNet uses 2`。

训练命令如下：

```bash
./build/tools/caffe train -solver models/finetune_flickr_style/solver.prototxt -weights models/bvlc_reference_caffenet/bvlc_reference_caffenet.caffemodel -gpu 0
```

中文说明：`-solver` 指定 solver 文件，`-weights` 载入 AlexNet 参考模型权重作为微调起点，`-gpu 0` 指定第 0 块 GPU。完整的 solver 与 train_val 模板（含 `fc8_flickr` 层全文）见《参考手册篇》配置模板一章中的微调 solver 模板与分类层片段。

### 4.2 ROP 二分类微调（Fine-tuning for ROP）

原稿的配置放在 `caffe-master/models/finetune_alexnet_rop/` 下，各节的路径分别写作 `caffe-master/models/finetune_alexnet_rop/solver.prototxt` 与 `caffe-master/models/finetune_alexnet_rop/train_val.prototxt`。

**solver 的改动。** 与 4.1 的 flickr 版相比，ROP 版只有两处路径不同，其余取值（含 4.1 表中那两条注释与 `base_lr`、`stepsize` 的取值）完全一致：

### 4.3 GoogLeNet 微调与多分类头改造（Fine-tuning GoogLeNet）

Assuming you are trying to do image classification. These should be the steps for finetuning a model:

> 译：假设你要做的是图像分类，微调一个模型应当包含下面这些步骤：

1. Classification layer

> 译：1. 分类层

The original [classification layer "loss3/classifier"](https://github.com/BVLC/caffe/blob/master/models/bvlc_googlenet/train_val.prototxt) outputs predictions for 1000 classes (it's mum_output is set to 1000). You'll need to replace it with a new layer with appropriate num_output. Replacing the classification layer:

> 译：原来的[分类层 "loss3/classifier"](https://github.com/BVLC/caffe/blob/master/models/bvlc_googlenet/train_val.prototxt) 输出 1000 个类别的预测（它的 `mum_output` 被设为 1000，原文拼写如此）。你需要用一个 `num_output` 合适的新层来替换它。替换分类层时：

原文列出的三条要点：

- Change layer's name (so that when you read the original weights from caffemodel file there will be no conflict with the weights of this layer).
- Change num_output to the right number of output classes you are trying to predict.
- Note that you need to change ALL classification layers. Usually there is only one, but GoogLeNet happens to have three: [loss1/classifier](https://github.com/BVLC/caffe/blob/master/models/bvlc_googlenet/train_val.prototxt#L904), [loss2/classifier](https://github.com/BVLC/caffe/blob/master/models/bvlc_googlenet/train_val.prototxt#L1667) and [loss3/classifier](https://github.com/BVLC/caffe/blob/master/models/bvlc_googlenet/train_val.prototxt).

> 译：三条要点分别是：改层名，这样从 caffemodel 读取原有权重时不会与这一层的权重冲突；把 `num_output` 改成实际要预测的类别数；注意必须改动**所有**分类层——通常只有一个，但 GoogLeNet 恰好有三个：`loss1/classifier`、`loss2/classifier` 和 `loss3/classifier`。

  bottom: "loss1/fc/bn"
  top: "loss1_c5/classifier"
  name: "loss1_c5/classifier"
  type: "InnerProduct"

    lr_mult: 10
    decay_mult: 1
  }

    decay_mult: 0
