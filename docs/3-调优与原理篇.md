## 1 Solver 与训练循环（Solver & the Training Loop）

本章说明求解器负责什么、有哪几种可选类型、一次迭代里发生什么，以及求解器在初始化阶段做了什么。

### 1.1 Solver 的职责（The Solver）

The solver orchestrates model optimization by coordinating the network’s forward inference and backward gradients to form parameter updates that attempt to improve the loss. The responsibilities of learning are divided between the Solver for overseeing the optimization and generating parameter updates and the Net for yielding loss and gradients.

> 译：求解器（solver）通过协调网络的前向推理与反向梯度来组织模型优化，形成试图降低损失的参数更新。学习的职责被分给两部分：Solver 负责监督优化过程并生成参数更新，Net 负责给出损失与梯度。

The Caffe solvers are:

> 译：Caffe 提供的求解器有：

| Solver | 类型（type） |
| --- | --- |
| Stochastic Gradient Descent | `type: "SGD"` |
| AdaDelta | `type: "AdaDelta"` |
| Adaptive Gradient | `type: "AdaGrad"` |
| Adam | `type: "Adam"` |
| Nesterov’s Accelerated Gradient | `type: "Nesterov"` |
| RMSprop | `type: "RMSProp"` |

表中第二列就是 solver.prototxt 里 `type` 一项要填的字符串。solver.prototxt 各参数的逐个说明与取值一览由《参考手册篇》的「solver.prototxt 参数速查」承载，本篇不再逐参数重复。

The solver scaffolds the optimization bookkeeping and creates the training network for learning and test network(s) for evaluation.

> 译：求解器搭建起优化所需的记账框架，并创建用于学习的训练网络与用于评估的测试网络。

下面这条列表说明求解器具体做哪些事，列表保留英文原文：

1. iteratively optimizes by calling forward / backward and updating parameters
2. (periodically) evaluates the test networks
3. snapshots the model and solver state throughout the optimization
4. where each iteration
   1. calls network forward to compute the output and loss
   2. calls network backward to compute the gradients
   3. incorporates the gradients into parameter updates according to the solver method
   4. updates the solver state according to learning rate, history, and method

to take the weights all the way from initialization to learned model.

> 译：一路把权重从初始值带到训练好的模型。

Like Caffe models, Caffe solvers run in CPU / GPU modes.

> 译：与 Caffe 模型一样，Caffe 的求解器运行在 CPU / GPU 两种模式下。

## 本章要点（Key Points）

- Solver 负责监督优化过程并生成参数更新，Net 负责给出损失与梯度。
- 类型速查：Stochastic Gradient Descent、AdaDelta、Adaptive Gradient、Adam、Nesterov’s Accelerated Gradient、RMSprop 分别对应 `type: "SGD"`、`type: "AdaDelta"`、`type: "AdaGrad"`、`type: "Adam"`、`type: "Nesterov"`、`type: "RMSProp"`。
- 求解器每轮迭代做四件事：前向算出输出与损失、反向算出梯度、按所用方法把梯度并入参数更新、按学习率与历史更新求解器状态。
- 求解器的构建发生在 `Solver::Presolve()`：日志依次给出读到的配置、网络初始化、反传标记与测试网络创建，最后是 `Solver scaffolding done.`；日志带原始时间戳与 `caffe.cpp:90`、`solver.cpp:32`、`net.cpp:356` 这样的源码行号，换一个 Caffe 版本之后这些行号可能不再对应。
- solver.prototxt 各参数的含义见《参考手册篇》的「solver.prototxt 参数速查」。

### 2.1 随机梯度下降（Stochastic Gradient Descent, SGD）

Stochastic gradient descent ( `type: "SGD"` ) updates the weights W by a linear combination of the negative gradient ∇L(W) and the previous weight update Vt. The learning rate α is the weight of the negative gradient. The momentum μ is the weight of the previous update.

> 译：随机梯度下降（`type: "SGD"`）用负梯度 ∇L(W) 与上一轮权重更新 Vt 的线性组合来更新权重 W。学习率 α 是负梯度的权重，动量 μ 是上一轮更新的权重。

Formally, we have the following formulas to compute the update value Vt+1 and the updated weights Wt+1 at iteration t+1, given the previous weight update Vt and current weights Wt:

> 译：形式化地说，给定上一轮的更新量 Vt 与当前权重 Wt，第 t+1 次迭代的更新量 Vt+1 与更新后的权重 Wt+1 由下面的公式计算：

```text
Vt+1=μVt−α∇L(Wt)
Wt+1=Wt+Vt+1
```

The learning “hyperparameters” (α and μ) might require a bit of tuning for best results. If you’re not sure where to start, take a look at the “Rules of thumb” below, and for further information you might refer to Leon Bottou’s Stochastic Gradient Descent Tricks [1].

> 译：学习「超参数」（α 与 μ）可能需要一点调参才能得到最好结果。如果不确定从哪里开始，可以看下面的「经验规则」；更多信息可以参考文献 Leon Bottou 的 Stochastic Gradient Descent Tricks [1]。

[1] L. Bottou. Stochastic Gradient Descent Tricks. Neural Networks: Tricks of the Trade: Springer, 2012.

要点：

- 更新量 `Vt+1=μVt−α∇L(Wt)`，新权重 `Wt+1=Wt+Vt+1`。
- α 是负梯度的权重（学习率），μ 是上一轮更新的权重（动量）。
- 原文指出 α、μ 可能需要调参，并指向下面的「学习率与动量的经验规则」以及 Bottou 的 Stochastic Gradient Descent Tricks [1]。

## 3 学习率与动量的经验规则（Rules of Thumb: Learning Rate & Momentum）

A good strategy for deep learning with SGD is to initialize the learning rate α to a value around `α≈0.01=10−2`, and dropping it by a constant factor (e.g., 10) throughout training when the loss begins to reach an apparent “plateau”, repeating this several times.

> 译：用 SGD 做深度学习的一个好策略是把学习率 α 初始化到 `α≈0.01=10−2` 附近，并在训练过程中、当损失开始进入明显的「平台期」时按固定倍数（例如 10）把它降下来，这个过程重复若干次。

Generally, you probably want to use a momentum `μ=0.9` or similar value. By smoothing the weight updates across iterations, momentum tends to make deep learning with SGD both stabler and faster.

> 译：一般来说，动量大概取 `μ=0.9` 或相近的值。动量平滑了各次迭代之间的权重更新，往往能让 SGD 的深度学习训练既更稳定又更快。

> 译：这正是 Krizhevsky 等人 [1] 在 ILSVRC-2012 竞赛中一举夺魁的 CNN 作品所用的策略；Caffe 让这一策略很容易在 `SolverParameter` 里实现，就像我们在 `./examples/imagenet/alexnet_solver.prototxt` 中对 [1] 的复现那样。


### 4.1 weight_decay 的含义与取值（weight_decay）

The weight_decay meta parameter govern the regularization term of the neural net.

> 译：`weight_decay` 这个元参数掌管神经网络的正则项。

During training a regularization term is added to the network's loss to compute the backprop gradient. The weight_decay value determines how dominant this regularization term will be in the gradient computation.

> 译：训练时会给网络的损失加上一个正则项，用来计算反向传播的梯度。`weight_decay` 的取值决定了这一正则项在梯度计算中有多主导。

As a rule of thumb, the more training examples you have, the weaker this term should be. The more parameters you have (i.e., deeper net, larger filters, larger InnerProduct layers etc.) the higher this term should be.

> 译：按经验，训练样本越多，这一项应当越弱；参数越多（例如网络更深、滤波器更大、InnerProduct 层更大等），这一项应当越高。

> 译：Caffe 也允许你在 L2 正则化（默认，权重平方之和）与 L1 正则化（权重绝对值之和）之间选择，只要设置


> 译：不过由于多数情况下权重都是较小的数（即 -1<w<1），权重的 L2 范数会明显小于其 L1 范数。因此如果选择 `regularization_type: "L1"`，可能需要把 `weight_decay` 调到明显更小的值。

- 正则化默认为 L2（权重平方之和），可用 `regularization_type: "L1"` 换成 L1（权重绝对值之和）；因为权重通常小于 1，改用 L1 时 `weight_decay` 可能要调到明显更小。原文括号里还提到 L0 范数（取零值的权重总数），并说 L0 与 L1 倾向于得到稀疏解，但只给了这一句说明，没有给出 L0 的设置方法。
- 学习率可以在训练中变化，正则化权重全程固定。
- 逐层衰减用网络定义文件里的 `decay_mult`，实际生效的衰减率是 `decay_mult*weight_decay`，`decay_mult: 0` 表示该层不做权重衰减。
- 原文的小节标题写作 `decay_multi`，正文与 prototxt 写作 `decay_mult`，本篇保留这一名称不一致。

## 5 参数更新、快照与恢复（Updating Parameters, Snapshot & Resume）

### 5.1 参数更新（Updating Parameters）

The actual weight update is made by the solver then applied to the net parameters in `Solver::ComputeUpdateValue()`. The `ComputeUpdateValue` method incorporates any weight decay r(W) into the weight gradients (which currently just contain the error gradients) to get the final gradient with respect to each network weight. Then these gradients are scaled by the learning rate α and the update to subtract is stored in each parameter Blob’s `diff` field. Finally, the `Blob::Update` method is called on each parameter blob, which performs the final update (subtracting the Blob’s `diff` from its `data`).

> 译：真正的权重更新由求解器完成、再作用到网络参数上，入口是 `Solver::ComputeUpdateValue()`。`ComputeUpdateValue` 会把权重衰减 r(W) 并入权重梯度（此时梯度里只有误差梯度），得到对每个网络权重的最终梯度；随后这些梯度按学习率 α 缩放，要减去的更新量存进每个参数 Blob 的 `diff` 字段；最后对每个参数 blob 调用 `Blob::Update` 完成最终更新（用 Blob 的 `data` 减去其 `diff`）。

### 5.2 快照与恢复（Snapshotting and Resuming）

The solver snapshots the weights and its own state during training in `Solver::Snapshot()` and `Solver::SnapshotSolverState()`. The weight snapshots export the learned model while the solver snapshots allow training to be resumed from a given point. Training is resumed by `Solver::Restore()` and `Solver::RestoreSolverState()`.

> 译：求解器在训练过程中通过 `Solver::Snapshot()` 与 `Solver::SnapshotSolverState()` 保存权重与自身状态。权重快照导出学到的模型，而求解器快照让训练可以从某个点恢复；恢复由 `Solver::Restore()` 与 `Solver::RestoreSolverState()` 完成。

Weights are saved without extension while solver states are saved with `.solverstate` extension. Both files will have an `_iter_N` suffix for the snapshot iteration number.

> 译：权重保存时不带扩展名，求解器状态保存为 `.solverstate` 扩展名。两类文件都会带上 `_iter_N` 后缀，表示快照所在的迭代号。

Snapshotting is configured by:

> 译：快照由下面这些配置项控制：

```prototxt
# The snapshot interval in iterations.
snapshot: 5000
# File path prefix for snapshotting model weights and solver state.
# Note: this is relative to the invocation of the `caffe` utility, not the
# solver definition file.
snapshot_prefix: "/path/to/model"
# Snapshot the diff along with the weights. This can help debugging training
# but takes more storage.
snapshot_diff: false
# A final snapshot is saved at the end of training unless
# this flag is set to false. The default is true.
snapshot_after_train: true
```

in the solver definition prototxt.

> 译：这些配置写在 solver 定义 prototxt 里。

配置项注释里的要点：`snapshot_prefix` 是相对于调用 `caffe` 工具的路径、而不是 solver 定义文件所在的目录；`snapshot_diff` 会把 diff 与权重一起存下来，便于调试但更占存储；`snapshot_after_train` 默认为 true，除非置为 false，否则训练结束时会保存一份最终快照。

## 本章要点（Key Points）

- 参数更新在 `Solver::ComputeUpdateValue()` 中完成：把权重衰减并入梯度、按学习率 α 缩放、把要减去的量写进参数 Blob 的 `diff`，再由 `Blob::Update` 用 `data` 减 `diff`。
- 快照分两类：权重快照导出模型（无扩展名），solver 快照保存训练状态（`.solverstate`），两者都带 `_iter_N` 后缀。
- 训练恢复由 `Solver::Restore()` 与 `Solver::RestoreSolverState()` 完成。
- `snapshot_prefix` 相对的是调用 `caffe` 工具的路径，不是 solver 定义文件的位置。
- `snapshot_diff: false` 是默认写法，注释说明打开它有助于调试但更占存储；`snapshot_after_train: true` 是默认值，训练结束会存最终快照。

### 6.1 学习率与 stepsize 的取舍（base_lr / stepsize）


两行注释与两处取值的对照如下，数值都取自上面的原文：

| --- | --- | --- | --- |
| `base_lr` | 0.001 | 0.01 | lr for fine-tuning should be lower than when starting from scratch |
