# 篇一 环境搭建篇（Environment Setup）

本篇导语：本篇解决「从一台裸机到能跑训练」的全部环境问题。第 0 章固定参考硬件与软件基线，并说明操作系统的取舍和两个 Caffe 分支各自的用途；第 1 章装 GPU 运行环境（NVIDIA 驱动、CUDA 8.0、cuDNN 5.1），每一步都用官方自检程序验收；第 2 章编译 Caffe，包括系统依赖、BVLC 官方分支、NVIDIA 分支和 pycaffe；第 3 章是可选的组件部署（DIGITS、py-faster-rcnn 及其依赖）；第 4 章说明外置数据盘怎么挂载。读本篇之前只需要一台装好 Ubuntu 的机器、一块 NVIDIA 显卡和一根能上网的网线，不需要预先了解 Caffe。本篇的命令与报错文本全部按原始记录保留，只按主题重排，因此个别地方会出现两处笔记写法不一致的情况，遇到时按文中提示自行判断。

#### 报错：libEGL.so.1 不是符号链接（/sbin/ldconfig.real: libEGL.so.1 is not a symbolic link）

```text
Processing triggers for libc-bin (2.23-0ubuntu7) ...
/sbin/ldconfig.real: /usr/lib/nvidia-375/libEGL.so.1 is not a symbolic link

/sbin/ldconfig.real: /usr/lib32/nvidia-375/libEGL.so.1 is not a symbolic link
```

这是 `libc-bin` 的触发器在跑 `ldconfig` 时打印的告警：`/usr/lib/nvidia-375` 与 `/usr/lib32/nvidia-375` 下的 `libEGL.so.1` 不是指向带版本号真实库文件的符号链接，所以动态链接器找不到它应该指向哪个版本。修法是先把现有的 `libEGL.so.1` 改名备份，再手工建立指向真实库文件的软链。

Solution:

> 译：解决办法：

```bash
sudo mv /usr/lib/nvidia-375/libEGL.so.1 /usr/lib/nvidia-375/libEGL.so.1.org

sudo mv /usr/lib32/nvidia-375/libEGL.so.1 /usr/lib32/nvidia-375/libEGL.so.1.org

sudo ln -s /usr/lib/nvidia-375/libEGL.so.375.66 /usr/lib/nvidia-375/libEGL.so.1

sudo ln -s /usr/lib32/nvidia-375/libEGL.so.375.66 /usr/lib32/nvidia-375/libEGL.so.1
```

四条命令两两成对：先备份 64 位与 32 位的 `libEGL.so.1`，再为两者各建一条指向 `libEGL.so.375.66` 的软链。

中文提示（驱动小版本不一致）：本节软链指向的真实库是 `libEGL.so.375.66`，而 1.3 节 `find` 输出里 `libnvcuvid` 的实际文件名是 `libnvcuvid.so.375.26`——两处笔记的驱动小版本不一致，本手册不做统一。执行前请先看 `/usr/lib/nvidia-375/` 与 `/usr/lib32/nvidia-375/` 目录下实际存在的库文件名，再照本节的形式替换；原文没有给出动态取版本的命令，这里也不新增命令。

### 1.3 CUDA 样例编译与自检（CUDA Samples & Self-check）

装完 CUDA 后编译官方 samples，这一步会先暴露 gcc 版本过高与 `-lnvcuvid` 两个报错，最后用 `deviceQuery` 做验收。

```bash
cd /usr/local/cuda-8.0/samples/
sudo make all
```

进入 `/usr/local/cuda-8.0/samples/` 后整体编译。另有一处笔记此处写作 `sudo make -j10 all`，本手册保留 `sudo make all`；两者只是并行度不同。

#### 报错：gcc 版本不受支持（gcc version not supported. The system uses gcc 6）

原文的 Solution 是改 CUDA 自带的头文件：

```bash
sudo gedit /usr/local/cuda/include/host_config.h
```

```text
// comment out the #error line

#if __GNUC__ > 5
// #error -- unsupported GNU version! gcc versions later than 5 are not supported!
```

这一段是要在 `host_config.h` 里改的内容：把 `#if __GNUC__ > 5` 下面那行 `#error -- unsupported GNU version! gcc versions later than 5 are not supported!` 注释掉。CUDA 8.0 的头文件在检测到 GCC 主版本大于 5 时直接报错终止编译，所以要么绕过这个检查，要么真的把编译器降到 5。

原文并列给出的第二条解法是装 gcc 5 并把它设为默认：

```bash
// install gcc 5 and set it as default gcc
// To figure out the current priorities of gcc
update-alternatives --query gcc
// Install gcc 5
sudo apt-get install gcc-5
update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-5 50 
update-alternatives --install /usr/bin/gcc gcc /usr/bin/gcc-6 50
// Make sure gcc 5 is the default
update-alternatives --config gcc
```

这段里的注释用的是 `//`，并不是合法的 bash 注释，原文如此，命令本身未做改动。命令依次做四件事：查当前 gcc 的候选优先级、安装 gcc-5、把 gcc-5 与 gcc-6 都注册到 `update-alternatives`、用 `--config gcc` 选中 gcc-5。原文把两条解法并列给出，没有说明孰先孰后，也没有说明是否必须二选一。

### 本章要点（Key Points）

- 驱动用「附加驱动」里的 NVIDIA 二进制驱动，应用更改后重启，分辨率恢复即成功。
- CUDA 8.0 用 16.04 的本地 deb 仓库包（8.0.61）装在 16.10 上；装包时会出现 `libEGL.so.1` 软链告警，按 1.2 的备份加软链修好。
- 编译 CUDA samples 会遇到 gcc 版本过高与 `cannot find -lnvcuvid` 两个错，分别用注释 `host_config.h` 的 `#error`（或切到 gcc-5）与修改 `findgllib.mk` 的 `UBUNTU_PKG_NAME` 解决。
- `deviceQuery` 输出 `Result = PASS` 才算 CUDA 装好；cuDNN 用 `mnistCUDNN` 验证，看到 `cudnnGetVersion() : 5110` 与 `Result of classification: 5` 即可。

### 3.5 编译 Cython 扩展（Building Cython Extensions）

## 4 数据存储（Data Storage）

本章只有一节：把外置数据盘挂进系统，供数据集读写。原文只有一台机器的实测记录，步骤本身对其它机器同样适用。

### 4.1 外置数据盘挂载（Mounting External Storage）

原文先看块设备与分区，再确认 `/dev` 下的设备节点，最后把分区挂到一个固定目录。

```text
zys@ubuntu:~/DIGITS$ lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINT
sr0          11:0    1  1024M  0 rom  
sda           8:0    0 931.5G  0 disk 
└─sda1        8:1    0 931.5G  0 part /media/zys/Seagate Backup Plus Drive
nvme0n1     259:0    0 238.5G  0 disk 
├─nvme0n1p5 259:5    0  14.9G  0 part [SWAP]
├─nvme0n1p3 259:3    0    16M  0 part 
├─nvme0n1p1 259:1    0   450M  0 part 
├─nvme0n1p6 259:6    0 105.1G  0 part /
├─nvme0n1p4 259:4    0   118G  0 part /media/zys/0A24AF0D24AEFAB9
└─nvme0n1p2 259:2    0   100M  0 part 
```

`lsblk` 的输出里要关注的是 `sda1` 这一行：`sda` 是一块 931.5G 的盘，只有一个分区 `sda1`，当时它的挂载点已经是 `/media/zys/Seagate Backup Plus Drive`（桌面环境自动挂载的结果）。同一份输出里还能看到系统盘 `nvme0n1` 的六个分区，其中 `nvme0n1p6` 挂在 `/`。

```text
zys@ubuntu:~$ ll /dev | grep sda1
brw-rw----   1 root disk      8,   1 Mar  7 22:31 sda1
```

这条命令确认 `/dev` 下确实存在设备节点 `sda1`（类型 `brw-rw----`、属主 `root disk`、主次设备号 `8, 1`）。

```bash
mkdir -p ~/seagate  // create if not exist
sudo mount /dev/sda1 ~/seagate
```

先建目录 `~/seagate`（原文注释 `create if not exist`），再把 `/dev/sda1` 挂到它上面。

中文提示（三处笔记的路径不一致）：数据准备命令里用的是 `/mnt/seagate/ROP_Unclassified_2016/`，`lsblk` 显示的桌面自动挂载点是 `/media/zys/Seagate Backup Plus Drive`，而这里的挂载命令挂到的是 `~/seagate`——同一块盘在不同笔记里被写在三个位置。要特别注意的是：如果分区已经被桌面环境自动挂载，再手工 `mount` 一次会在两个目录上重复挂载同一个分区，读写可能只落在其中一处，后面按路径找数据集时就会找不到文件。本手册保留原文的三种写法不做统一；实际使用时先看 `lsblk` 的 MOUNTPOINT 列，选定一个目录后前后统一，必要时先卸载自动挂载点再手工挂载。

### 本章要点（Key Points）

- 先用 `lsblk` 看清盘与分区的设备名（本机数据盘是 `sda1`）以及它当前的挂载点。
- 用 `ll /dev | grep sda1` 确认设备节点存在。
- 建好挂载目录后手工挂载：`mkdir -p ~/seagate` 加 `sudo mount /dev/sda1 ~/seagate`。
- 三处笔记的路径写法不同（`/mnt/seagate`、`/media/zys/Seagate Backup Plus Drive`、`~/seagate`），要避免同一分区被自动挂载与手动挂载重复挂到两个目录上。
